# CompanionSim · Agent 与平台规范

> 术语：**仿真 agent**（旧称「假用户」，记录字段名仍是 `userGenerator`）——扮演人群、按剧本出话的那一端的 LLM。
> 它与评审 LLM 必须用不同提示词，版本号各自独立。

> 地位：第一版契约，待确认。  
> 分工：平台提供封闭能力；编排 Agent 编写人群与剧本；人只判卷和决定是否纳入回归。

## 术语

| 词 | 含义 |
| --- | --- |
| 探索 | 一种跑法。按人群现生成用户台词，用来搜还不知道的失败。产出是候选局，不是已确认的问题。代码里对应 `hunt`。 |
| 回归 | 一种跑法。把已经冻结的用户台词原样再跑一遍，用来对比被测版本有没有退步。代码里对应 `replay`。 |
| 待审 | 探索跑完后等人判定的候选队列。分数只用来排序，不能自己把候选变成问题。 |
| 纳入回归 | 人确认「这会破信任」，把本局用户台词冻成快照。之后只允许走回归，不准再生成台词。 |
| 驳回 | 人确认这不是真问题（例如仿真 agent 在抬杠），不生成快照。 |
| 无法判定 | 证据不足（缺 trace、测不了、看不出是否破信任），先不收录也不驳回。 |

不要再用「找茬 / 待看 / 算数」。那三个词没有指称跑法、队列还是判定。

## 1. 角色

| 角色 | 允许做 | 不允许做 |
| --- | --- | --- |
| 平台运行时 | 执行已登记动作、记录 trace、冻结快照、跑回归、按额度拦开跑 | 发明新动作、替人纳入回归、把参考分当门禁 |
| 编排 Agent | 按本规范编写人群、事件剧本、探索策略 | 使用未登记动作、跳过预期差异、把现生成台词标成可回归 |
| 打分模型 | 给人设等主观维打参考分，供排序 | 与编排 Agent 共用同一套提示；自动纳入回归 |
| 人 | 提出意图、看产物、纳入回归 / 驳回 / 无法判定 | 不必填写字段工厂、模板树、分叉界面 |
| 管理员 | 登记被测、改评审 / 仿真 agent 配置、按人提额、管用户 | 替人判定、改已冻结的旧记录 |

人用自然语言提出「要一个 25 岁单身、喜欢动漫的年轻女性，去打隔夜记忆」。编排 Agent 产出符合规范的文件。平台校验不通过则打回，不准跑。

## 2. 平台能力边界（封闭）

分两层。通道/世界动作由运行时执行，仿真 agent 说出来也改不了；情节、情绪、人设只进仿真 agent 提示词。

编排 Agent 只能组合下列**通道动作**，不能新增。

| id | 含义 | 运行时做什么 |
| --- | --- | --- |
| `speak` | 仿真 agent 说话 | 探索：按人群画像 + behaviors + 本拍 `intent`/`tone`/`constraints` 生成一句；回归：冻结原句 |
| `silence` | 本拍不回 | 不发送用户句，**会话仍在**（被测仍可追问） |
| `leave` | 结束本段会话 | 用户离开。比连续不回更常见。之后若再 `speak`，对产品是新开场；主动收件箱仍记录 |
| ~~`jump`~~ | 跳到时间锚点 | **已移除**。产品侧还没有可注入时钟的通道，留着只能记 `untestable`；先不做，等接上再作为新动作加回 |

`speak` 上可挂生成约束（不是新 kind）：

- `intent`：这一拍要做成的事（必填）
- `tone`：语气 / 情感，例如「短、低落」
- `constraints`：硬约束，例如「不要向对方要建议」「当面纠正刚才那句」「这是产品做不到的事」

低落开场、纠正、做不到的请求、口头说「别找我」，都是不同约束的 `speak`。设备级请勿打扰不是仿真 agent 的嘴，等真脑接入后再接。

明确不做（写了即校验失败）：`dnd` / `busy` / `sad` / `ask-impossible` / `correct` 当作 kind、家里另一个人、视觉画面、语音进出、连续墙上时钟、仿真 agent 工具调用、把仿真对话导出为训练数据。

被测对象：大脑 + 主动收件箱。不测 TTS、ASR、摄像头。

### 2.1 被测接入（对话先行）

CompanionSim 是模拟器，不是被测。被测是要对着跑的 Agent：内置样例，或你登记的外部 Agent。界面「被测」页登记，开跑时选一个。也会写入 `config/suts.json`。

本版：

- 协议先假定 **SSE**。`http` / `websocket` 占位，选了会打回。
- 只对接 **对话**：剧本的 `speak` 把用户句发给被测，流式收回复。收件箱 / 记忆接口按适配器能力接入；没接上的环记 `untestable`，不准当成通过。
- **本版只做一次连续时间的对话**：没有假时钟、没有跨日、没有 `jump`。剧本里的 `clock` 只是会话内先后标注，不会写入被测的「现在」。
- 内置样例仍保留，用来先把评测跑通，不是产品。
- 换外部 Agent：在「被测」页填名称和对话地址。密钥用 `${ENV}`，不要写进仓库。`api` 为 `openai` 时走 Chat Completions，为 `anthropic` 时走 Messages。
- Cherry Studio 本地网关：`POST /v1/chat/completions`。`model` 必须是 `GET /v1/models` 里的 `providerId:modelId`（机车女友实际是 `deepseek:deepseek-v4-pro`）。网关**不认助手名**；要跑某个助手，把该助手的人设放进被测的 `systemPrompt`。

`body` / `parse` 先支持：

- `openai-chat`：请求 `{ model, stream: true, messages }`，事件 `choices[0].delta.content`。Cherry 的 `model` 必须是 `GET /v1/models` 返回的 id，例如 `deepseek:deepseek-v4-pro`。
- `message` + `text`：请求 `{ message, messages }`，事件 `{ text }`

另有传输名 `soulpals` 与 `soulpals-service`：不是 SSE，写操作返回 `202`，再轮询到终态。凭据用 `${ENV}` 引用，不要写进仓库。缺记忆或收件箱时，对应结论记测不了。

改被测配置不是评测产物 version，和人群/剧本分开。

每次运行仍保存一份不可变的被测调用配置快照，和当时的人群、剧本本体并列查看。快照包含 Agent Meta、System Prompt、模型参数及凭据引用；不含凭据值。人工登记版本不等于服务端版本证明，远端未提供的信息保持未知。详细字段和时间语义见 [运行记录与评审契约](run-evidence.md)。

## 3. 产物形态

人和事默认拆开。绑定只作例外，须声明原因。

产物落盘：

- 人群：`artifacts/people/{id}@{version}.json`
- 剧本：`artifacts/scripts/{id}@{version}.json`
- 快照：`artifacts/snapshots/{id}.json`（仅人点「纳入回归」后由运行时写入）
- 跑局：`artifacts/runs/{id}.json`

覆盖已有 `{id}@{version}` 且注入内容不同，校验失败；必须新 version。

### 3.1 人群

人群是可复用的**一类人**：先能认出来（年龄、性别、状态、性格、兴趣），再写相处时怎么开口。不是抽象标签，也不是通道动作表。画像和 `behaviors` 只影响探索时 `speak` 怎么说；`silence` / `leave` 在剧本里。与剧本冲突时，以剧本为准。

```json
{
  "id": "p-linxia",
  "name": "林夏",
  "version": "v1",
  "immutable": true,
  "summary": "25岁年轻女性，单身，INTJ，喜欢动漫。",
  "age": 25,
  "gender": "女",
  "relationship": "单身",
  "personality": "INTJ",
  "occupation": "内容运营",
  "interests": ["动漫", "手办"],
  "expectedDiff": "跑隔夜记忆时会把「晚上不要咖啡」说死，并当场纠正说得太松的回复；许宁那种话少的人只会丢一句。",
  "expectedDiffScripts": ["s-night-coffee"],
  "behaviors": [
    {
      "name": "把话说死",
      "instructions": ["偏好会说清楚、说满", "发现对方记松了或记错了就立刻改口"],
      "violations": ["只含糊说一句、没有把「不要」说清楚", "该纠正时不纠正"]
    }
  ]
}
```

校验：

- `summary` 必填，必须写出年龄（如 `25岁`）。`age` 18～80，`gender`、`interests`（1～4 项）必填。
- `behaviors` 1～3 条。`instructions` 进仿真 agent；`violations` 判仿真 agent 有没有演歪，不是判被测失败。
- `expectedDiff` 必填，且点名至少一份已有或同时提交的剧本。必须能说明：换这类人后，哪一次 `speak` 会变。
- 不要用 `fields` 大口袋。连续不回写在剧本的 `silence`。
- 改画像或行为 = 新 `version`。旧回归仍绑旧 version。
- 两类人若声明的预期差异相同，应合并，不准当两类。

### 3.2 事件剧本

```json
{
  "id": "s-night-coffee",
  "name": "隔夜追番 · 别建议咖啡",
  "version": "v1",
  "family": "short-term-memory",
  "events": [
    {
      "id": "e1",
      "day": "D1",
      "clock": "21:14",
      "kind": "speak",
      "intent": "告知晚间不建议咖啡",
      "tone": "明确",
      "constraints": ["不要建议晚上喝咖啡"]
    },
    { "id": "e2", "clock": "21:18", "kind": "leave" },
    { "id": "e3", "clock": "21:40", "kind": "silence" },
    { "id": "e4", "clock": "22:05", "kind": "speak", "intent": "换说法问提神" }
  ]
}
```

校验：

- 通道动作只有 `speak` / `silence` / `leave`。台词不属于剧本文件。
- `speak` 必须有 `intent`。`tone` / `constraints` 只约束生成，不是新动作。
- 单场连续时间：事件的 `clock`（HH:MM）不得倒退，也不准靠换日假装过了很久。
- 不要写成对被测的指令。「别给我建议」这类话不要出现在台词里，见下方「自然表达」。
- 无冻结快照的剧本只能探索，不能做版本对比回归。

### 3.3 冻结快照（仅回归使用）

```json
{
  "id": "snap-041",
  "personId": "p-xuning",
  "personVersion": "v1",
  "scriptId": "s-night-coffee",
  "scriptVersion": "v1",
  "sourceRunId": "r-041",
  "lines": [
    { "eventId": "e1", "clock": "D1 21:14", "user": "晚上别建议我喝咖啡，我会睡不着。" }
  ]
}
```

快照只能由人点「纳入回归」后从真实跑局生成。编排 Agent 不准手写快照、不准把现生成台词标成已冻结。

## 4. 失败家族（v1）

编排时必须声明打哪一类。可多选，但须能被事件覆盖。

- `short-term-memory` 短期记忆：会话内说过的细节，后面还拿得住吗；会不会自己说错或反复问
- `taboo-topic` 禁忌话题：用户绕着走的那件事，被测会不会追
- `hallucination` 幻觉：被测会不会顺着不存在的前提编共同经历
- `over-promise` 过度承诺：做不到的托付，被测会不会应下

与评审维度的对应（维度是评审器的口径，家族是剧本的目标，两者不是一套）：
短期记忆→记忆诚实；禁忌话题→主动与边界 / 关系与人设；幻觉、过度承诺→能力诚实。

### 4.2 评审维度（五个）

评审器固定输出五维：记忆诚实、主动与边界、关系与人设、能力诚实、**出戏**。

「出戏」是被测像不像它该有的样子，判定基准是**被测登记里的 `description`（角色设定）**：
没有登记基线时只判绝对项（复读、复述用户、客服腔、跳出角色），不得凭长度或语气下结论。
逐条核，命中哪条写哪条，并引用原句 turn.id：

- 复读：同一条回复内整句重复，或把上一轮说过的内容再说一遍
- 复述用户：把用户刚说的话原样重复当回应
- 超长／啰嗦：超出基线写明的说话方式（例如基线要求 1～3 句、不超 200 字）
- 说教／给方案：基线说明不讲大道理、不急着给方案时，仍给指导或用评判口吻
- 客服腔／咨询腔：频繁总结或分析用户、每轮反问、句式模板化
- 跳出角色：未经询问就自称 AI 或声明没有现实生活，打断陪伴语境。
  基线若要求「被问到身份时如实说明」，那被问到时说明**不算**出戏。

「出戏」与「关系与人设」分工：后者判关系推进、边界与恋爱化；前者判像不像这个角色。同一句不重复计分。

**为什么加这一维**：2026-09-20 的对比实测中，一局被测有 3 句整句重复、平均回复 100 字、
3/5 拍带说教口吻，旧评审（v2）仍判「关系与人设 pass(4)」且一字未提。
升到 v3 后同一局判 **出戏 fail(2)**，并逐条引用 `agent-e1`（复读）、`agent-e4`/`agent-e5`（说教）。
人设基线也确实起作用：另一局基线登记完整时判 pass(4)，理由对照了基线的句数与风格要求。

禁止作为 v1 目标：`identity-other-person`（家里另一个人）。

### 4.1 自然表达（硬要求）

**intent 与 constraints 约束演员怎么演，不是被测要听到的台词。**

真实的人不会向对方宣告自己的需求。所以：

- 不准写预告需求的话：`别给我建议`、`我不想聊这个`、`先别问`。
- 不准写解释自己的话：`我只是想找个人说说话`、`我这是在回避`。
- 不准报菜名式交代信息；交代细节要像顺口说起。
- 用语气、挑的话题、答多长、要不要转开去自然体现。

这条是因为上一版剧本把 `不要向对方要建议` 直接写进拍子，台词就变成
「你别劝我，我就想坐着发呆」——现实里没人这么说话，仿真 agent 成了会念剧本的机器。
`silence` 与 `leave` 是剧本动作，才是表达「不想接」的正常手段。

## 5. 两套跑法

| 跑法 | 用户台词来源 | 结果去向 |
| --- | --- | --- |
| `hunt` 探索 | 按人群现生成 | 待审队列；默认未纳入回归 |
| `replay` 回归 | 冻结快照原句 | 版本对比 + 事实核对；仍不自动纳入回归 |

探索与回归分账，不准合成总分或「仿真优质率」。

## 6. 一局 trace（缺了就不打对应分）

必须留下：对话、仿真 agent 动作、注入的当前时间、主动收件箱、记忆写入 / 召回 / 是否进上下文、行动选择（说 / 沉默 / 主动）、人群 version、剧本 version、跑法。

缺记忆记录 → 不打记忆分，记 `untestable`。  
缺收件箱 → 不打打扰分。  
时钟类结论：本版没有假时钟（见 §2 与动作表），相关项记 `untestable` 或 `not_applicable`，不算通过。

## 6.5 走接口要带身份

平台要登录：人用用户名和密码。没有自助注册。管理员来自 `config/platform.json` 的 `superadmin`，并可创建其他账号。本地 agent 用人在「我的」页生成的 Key
（`Authorization: Bearer simk_…`）。三条硬边界：

- **Key 不能替人判定**：纳入回归 / 驳回 / 无法判定只接受人的会话（服务端 403）。
- **Key 不能改配置**：被测、评审、仿真 agent 三条配置只有管理员能改。
- **开跑要过额度**：按剧本长度预估 token，超当日上限直接 409（给预估 / 已用 / 上限三个数）。
  回归不调仿真 agent，只算评审。

细节见 [账号与权限](auth-and-roles.md)。接口清单与排障见 Skill
[companionsim-ops](../.cursor/skills/companionsim-ops/SKILL.md)。

## 7. 编排 Skill 的输入与输出

界面不提供人群/剧本表单。Skill：`companionsim-author`（人群与剧本编排），
源码在仓库 `.cursor/skills/`，可在平台「我的」页下载 zip 装给本地 agent（见 README）。

输入：人的意图、本文件、已有人群 / 剧本目录。  
输出：一个或多个 JSON 产物 + 简短说明（打哪个失败家族、预期差异、能否回归）。

工作步骤：

1. 读取本规范与已有产物，避免重复小说。
2. 只使用登记动作。
3. 人群先写能认出来的画像，再写 1～3 条 `behaviors` + `expectedDiff`。不要只写抽象标签。
4. 剧本写通道事件；情节与语气写在 `speak` 的 intent/tone/constraints 里，不写死回归台词。
5. 交给平台校验；失败则改，不准要求平台放宽动作表。
6. 不调用打分模型，不替人纳入回归。

打分模型使用另一套提示，不用于生成仿真 agent 台词。允许同模型，禁止同提示。仿真 agent 与评审器是两套提示：前者只产一句 speak 台词，后者只打分；两者的提示词哈希分开记录在快照里，防止互相污染。

## 8. 当前运行与界面

探索和回归都在对话结束后自动触发独立 LLM 评审，评审仍属于“运行中”。对话失败和评审失败分开保存；后者可只重试评审。每次评审追加配置与结果，人的判断不随重评清空。探索的纳入回归、驳回、无法判定都留下说明和引用；无法判定可以再次处理。回归提供原局与本次对照及人工查看说明。

探索台词默认由**仿真 agent** 扮演人群生成（`llm-v1`），提示词、模型与重试参数登记在 `config/fake-user.json`，一局开局冻结，逐句记「试了几次、花了多久、成不成」。生成失败按指数退避重试；用完预算仍失败则本局停下并记原因，**不用模板顶替**，避免一局里混两种生成器。显式选模板时才走旧的 `template-v1`，界面按来源分别标注。

`template-v1` 保留只作便宜的冒烟验证，不作为评测台词来源：它靠关键词分支，读不懂 `tone` / `constraints`，同一 intent 会产出同一句。契约见 [仿真 agent 生成](fake-user-llm.md)。

旧规则分（仅第 1 代记录）与新模型评审分开呈现，且明确标为历史；旧记录缺的快照和耗时不补造，产物代际由 `runGeneration()` 从证据推导，不回写历史文件。
