# CompanionSim 架构

CompanionSim 是虚拟陪伴与角色扮演 Agent 的模拟器。它用可配置的人群和剧本，让一个仿真用户与被测 Agent 对话，再用另一个模型评审。人决定哪几局对话冻结，冻结后的台词用于回归。

本文只描述当前系统。读者是要改代码、接入被测，或自己部署的人。

## 1. 系统边界

平台提供封闭的运行能力：登记被测、保存人群与剧本、按剧本推进一局对话、调用评审、留下证据、接受人的判定。

人群和剧本的写法在平台之外，由编排说明约束，经接口提交。平台校验通过才落盘。编排者不能发明通道动作，也不能改写一局已经发生的对话。

仿真对话不进入训练，也不作为发版门禁。探索负责发现可疑对话，回归负责用冻结台词对比版本。两件事不合成一个分数。

## 2. 分层

```text
src/          React 界面。单页状态在 App.tsx，没有独立路由库。
shared/       无副作用的契约：领域类型、通道动作、跑局状态、评审证据约束。
server/       Node HTTP 运行时。开发时挂在 Vite 上，生产时由 server/main.ts 同进程托管静态文件和 /api。
config/       可编辑配置。平台凭据在 config/platform.json，不进 git。
artifacts/    人群、剧本、运行记录、回归快照。文件即存储。
```

`server/http.ts` 的 `ROUTES` 是唯一业务入口。每条路由声明访问级别：`public`、`read`、`artifact`、`run`、`decide`、`admin`。未登记的路径返回 404。`decide` 只允许登录用户，API Key 不能代替人做判定。

```text
界面 ── /api/* ── http.ts（ROUTES + 访问级别）
                    ├─ 登录、Key、配额、用户
                    ├─ runtime：开局、对话、评审、判定
                    ├─ MySQL：用户、会话、Key、审计、配额
                    └─ 文件：config/ 与 artifacts/
```

## 3. 一局仿真

探索和回归共用编排，差别在台词从哪来。

探索：

1. 选定人群版本、剧本版本、被测。开局冻结这三者以及仿真用户、评审的配置快照。
2. 剧本按事件推进。通道动作只有 `speak`、`silence`、`leave`。
3. `speak` 时，仿真模型按人群和当前事件生成一句台词，送给被测，记下回复、首字时间和总耗时。
4. 对话结束后读取被测能提供的记忆和收件箱，做事实核对，再自动评审。
5. 人在待审队列里选择纳入回归、驳回或无法判定。纳入回归后，平台把这局台词写成快照。

回归：

1. 从冻结快照发起，沿用原来的用户台词和事件。
2. 可以更换被测或版本。
3. 不再调用仿真模型。

评审失败可以单独重试，不重跑对话。对话是否结束、评审是否结束、人是否已判定，是三件分开的状态，派生规则在 `shared/run-state.ts`。

被测通过适配器接入，接口在 `server/sut.ts`。当前默认使用的传输：

| 传输 | 用途 |
| --- | --- |
| `fixture` | 进程内样例，用来把流程跑通 |
| `sse` | 外部对话接口。`api` 为 `openai` 时走 Chat Completions；为 `anthropic` 时走 Messages |

同一被测在一局里使用独立的仿真身份，避免多个人群共用一份记忆。同一记忆域内的运行串行执行。进程内锁因此要求单实例部署；多副本之前要先把锁移出进程。

## 4. 身份与配额

登录是用户名和密码。没有自助注册。

首次启动用 `config/platform.json` 里的管理员用户名和密码哈希建立管理员。管理员在管理页创建其他账号。密码只存 scrypt 哈希，格式由 `server/password.ts` 定义，生成命令是 `npm run admin-password`。

本地 Agent 使用用户签发的 API Key。Key 可以读取、提交素材和发起运行，不能做纳入回归、驳回或改平台配置。改被测、仿真模型和评审模型的权限属于管理员。

操作人写在 MySQL 的 `audit_log`，不写进人群或剧本 JSON。这两类文件按白名单校验，旁路字段会把一次原样提交看成内容已变。

配额在开跑前按预估占用当日额度，跑完用实际用量回写。超过当日上限时拒绝新开局，不中断已经开始的一局。

## 5. 模型接口

被测、仿真用户、评审都指向可配置的 HTTP 接口，而不是写死某一家供应商。

- 被测登记在 `config/suts.json`。默认是 `fixture`。
- 仿真用户的连接和模型在 `config/fake-user.json`。
- 评审的连接和模型在 `config/judge.json`。

两条 LLM 配置通过 `connectionSutId` 引用 `suts.json` 里的一条连接。连接的 `api` 取 `openai` 或 `anthropic`。密钥用 `${ENV}` 写在配置里，值放在环境变量或 `.env.local`，不进 git。

仿真模型和评审模型应当属于不同模型家族，避免同一模型自己出题自己打分。示例配置把二者分成两家接口；如果只接一家，仍应使用两个不同模型。

缺记忆、缺收件箱或其他本局没有的证据时，对应结论记为测不了，不补成通过。事实核对只判断这局有没有资格下结论；语义判断交给评审模型。评审对照被测登记的角色说明，其中一维是角色是否出戏。

## 6. 数据

MySQL 保存平台状态：`users`、`sessions`、`api_keys`、`audit_log`、`quota_daily`、`quota_overrides`。表由 `npm run db:migrate` 创建，已发布的迁移只追加、不改写。

文件保存领域产物：

| 路径 | 内容 | 谁写入 |
| --- | --- | --- |
| `artifacts/people/`、`artifacts/scripts/` | 带版本号的人群和剧本 | 校验通过后的提交 |
| `artifacts/runs/` | 一局一条，含对话、请求、评审和事实核对 | 运行时 |
| `artifacts/snapshots/` | 冻结台词 | 仅在人选择纳入回归之后 |

同版本人群或剧本若内容不同，校验拒绝覆盖。

## 7. 部署

公开的运行方式是单机 Docker Compose：一个应用进程加一个 MySQL 8。配置来自文件，不依赖外部配置中心。

本地开发是 `npm run dev`，同样使用本机 MySQL 和 `config/platform.json`。数据目录默认是仓库根；容器里用 `SIM_EVAL_DATA_ROOT` 指到挂载卷，使镜像和数据分开。

应用是单进程。开发态的 API 由 Vite 插件转发到同一套 `handle()`，生产态由 `server/main.ts` 提供。

## 8. 不变量

这些约束被测试或运行时直接执行，改动时要一起改：

1. 新接口必须登记到 `ROUTES` 并声明访问级别。
2. 回归路径不调用台词生成器。
3. 通道动作只有说话、沉默、离开。
4. 只有探索局被纳入回归后才写快照。
5. 评审失败与对话失败分开记录，可以只重试评审。
6. 没有证据的维度记为测不了。
7. 一局默认一个仿真身份；同一记忆域串行。
8. API Key 不能做人工判定，也不能改管理员配置。
9. 操作人不写入人群和剧本文件。

## 9. 本版不做

- 不把仿真时钟注入被测的「现在」。时间只用来标注对话先后。
- 不把异常对话自动聚类。人直接看待审队列。
- 不提供人机校准集。
- 被测的主动收件箱没有通用适配器时，该维度记为测不了。
- 不支持把 `http` 或 `websocket` 当作已实现的被测传输。
